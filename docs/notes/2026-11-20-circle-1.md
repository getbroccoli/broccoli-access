# Circle 1 decisions (2026-11-20)

Scope, setup and testing are in [circle 1](../circle1.md). This note keeps the reasons and the open checks.

## Rules for every circle

- A circle ships happy paths only, with simple screens, and every journey has an automated check.
- It leaves the next circle able to start on its own: the data model covers the whole product, the fake apps cover every connected app, and the edge cases it skipped are written down as the next circle's input.

## Why

- Self-hosted only: no managed version.
- "Use the Broccoli app" waits for a later circle. Google access tokens expire hourly, and renewing one needs the app's secret, so every instance would depend on a relay we run, for as long as it is connected. Admin scopes on a public app also need Google's verification, which is slow.
- Setup asks for every read scope the product needs, audit logs included, so a later circle needs no new consent.

## Live test organisation

- Google Cloud Identity Free: free, 50 users, APIs, and OAuth grant log events.
- The maintainer approves the instance's own Google app on it once; the refresh token is stored as a secret for live checks.
- Grants to other apps are created once by hand, signing in as each test user, because Google blocks automated sign-ins.
- Setup with the real consent screen is checked by a person; scans with the stored token can run unattended.

## Google limits found

- API call ("Activity") log events exist only on Enterprise Standard or higher and Cloud Identity Premium, not on Business editions or Cloud Identity Free. "Last used" cannot rely on them.
- Grant log events are available on every edition.

## To check in the fake apps design

- Internal OAuth apps need no Google verification.
- Redirect addresses need HTTPS or localhost; an instance on a bare internal IP cannot connect.
- Third-party grants need `admin.directory.user.security`, which can also revoke them; users and audit logs have read-only scopes.

## Before circle 1 starts

- The maintainer approves the data model and the fake apps design.
- The maintainer approves the Google app once on the test organisation.
- The maintainer starts Google's verification of the Broccoli Google app, needed before "Use the Broccoli app" ships.
